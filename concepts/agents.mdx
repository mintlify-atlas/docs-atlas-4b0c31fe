The ATD framework uses a **multi-agent architecture** where specialized agents collaboratively analyze dependency cycles. Each agent has a distinct role, prompt strategy, and token budget.

## Agent architecture

### Orchestration flow

From `explain_AS/engine.py:96-208`, the multi-agent orchestration follows this sequence:

<Steps>
  <Step title="Edge agents (parallel)">
    Analyze each directed edge in the cycle independently, explaining dependency relationships
  </Step>
  <Step title="Auxiliary agent (optional)">
    Provide additional context: boundary heuristics (Boundary), SCC structure (Graph), or none
  </Step>
  <Step title="Synthesizer agent">
    Combine edge reports and auxiliary context into a coherent cycle-level explanation
  </Step>
  <Step title="Review agent (optional)">
    Revise synthesizer output for clarity and consistency without adding new facts
  </Step>
</Steps>

## Edge agent

**File:** `explain_AS/agents/edge.py`

**Role:** Analyze a single directed edge A → B in the dependency cycle.

### Responsibility

The edge agent examines **why A depends on B** by analyzing the full source code of both files. It identifies:
- Specific import/using statements
- Which symbols from B are used by A
- The semantic purpose of the dependency

### Implementation

From `explain_AS/agents/edge.py:124-155`:


## Synthesizer agent

**File:** `explain_AS/agents/synthesizer.py`

**Role:** Combine multiple edge reports into a unified cycle-level explanation.

### Responsibility

The synthesizer receives:
- Edge reports for all edges in the cycle
- Optional auxiliary context (from boundary or graph agents)

It produces a coherent narrative explaining:
- How the cycle is formed (the circular dependency chain)
- Why the coupling exists (architectural interpretation)
- Impact on maintainability

### Implementation

## Boundary agent

**File:** `explain_AS/agents/boundary.py`

**Role:** Infer likely architectural boundaries from file paths and external connections.

### Responsibility

The boundary agent analyzes:
- File paths of nodes in the cycle
- Incoming edges from outside the cycle
- Outgoing edges to outside the cycle

It produces **heuristic** boundary inferences based on path patterns (e.g., `src/domain`, `src/persistence`).

<Note>
  The boundary agent operates on **path names only**, not source code. It's a lightweight heuristic complement to code-based analysis.
</Note>

## Graph agent

**File:** `explain_AS/agents/graph.py`

**Role:** Summarize how the cycle sits within its strongly connected component (SCC).

### Responsibility

The graph agent receives:
- The full SCC containing the cycle (all nodes and edges)
- The specific cycle being analyzed

It identifies:
- Hubs and bridges within the SCC
- External connections at the SCC level
- Structural risks when breaking cycle edges

### SCC context format

From `explain_AS/engine.py:32-59`:

```python
def _build_scc_text_from_report(scc_report: Dict[str, Any], scc_id: str) -> str:
    lines: List[str] = []
    lines.append(f"SCC id: {scc_id}")
    lines.append("")
    lines.append("Nodes:")
    for n in nodes:
        lines.append(f"- {n}")
    
    lines.append("")
    lines.append("Edges:")
    for e in edges:
        src = str(e.get("source") or "")
        tgt = str(e.get("target") or "")
        if src and tgt:
            lines.append(f"- {src} -> {tgt}")
    
    return "\n".join(lines).strip()
```

## Review agent

**File:** `explain_AS/agents/review.py`

**Role:** Revise the synthesizer output for clarity and internal consistency.

### Responsibility

The review agent is a **finalizer** that:
- Rewrites the synthesizer output to be clearer
- Ensures internal consistency
- Does NOT add new facts or interpretations
- Does NOT include meta-commentary or critique

<Note>
  **Hard constraint:** The review agent must output ONLY the final revised explanation, not a review report.
</Note>

## Agent execution guarantees

### Token budgets

All agents enforce strict token budgets to fit within the LLM context window:

| Agent | Min Output | Safety Margin | Total Reserved |
|-------|-----------|---------------|----------------|
| Edge | 2000 | 1000 | 3000 |
| Synthesizer | 3334 | 1000 | 4334 |
| Boundary | 2000 | 1000 | 3000 |
| Graph | 2000 | 1000 | 3000 |
| Review | 3667 | 1000 | 4667 |

### Truncation handling

From `explain_AS/budgeting.py`, the framework uses:

- **Hard caps:** 40,000 characters per file before token budgeting
- **Soft truncation:** Token-based truncation with "[TRUNCATED]" markers
- **Redistribution:** Unused token budget from small inputs is reallocated

### Error handling

From `explain_AS/llm.py`, the `Agent.ask()` method:

1. Validates token budgets before making the LLM call
2. Implements retry logic with exponential backoff
3. Returns exit code 42 on LLM unavailability
4. Writes transcript logs for debugging

## Auxiliary agent selection

Only **one** auxiliary agent can be active at a time:

```python
# From explain_AS/engine.py:79-87
def _get_auxiliary_agent(params: Dict[str, Any]) -> str:
    aux = str(params.get("auxiliary_agent") or "none").strip().lower()
    if aux not in {"none", "boundary", "graph", "review"}:
        raise ValueError(f"auxiliary_agent must be one of none|boundary|graph|review")
    return aux
```

<Accordion title="Which auxiliary agent should I use?">
  - **none:** Default; synthesizer uses only edge reports
  - **boundary:** When architectural layer violations are suspected
  - **graph:** When SCC structure and hubs are important
  - **review:** When explanation consistency is critical (research quality)
</Accordion>

## Minimal orchestrator mode

From `explain_AS/engine.py:90-93`, the framework also supports a minimal mode:

```python
def _run_minimal(*, cycle: Dict[str, Any], language: str) -> ExplainEngineResult:
    cycle_nodes = filtered_cycle_nodes([str(n) for n in (cycle.get("nodes") or [])], skip_init=True)
    prompt = build_minimal_prompt(cycle_nodes, language)
    return ExplainEngineResult(cycle_nodes=cycle_nodes, final_prompt_text=prompt)
```

Minimal mode:
- Skips all LLM calls
- Generates a basic prompt with cycle structure only
- Useful for testing or baseline comparisons

<Tip>
  Set `orchestrator: minimal` in mode configuration to use minimal mode.
</Tip>
