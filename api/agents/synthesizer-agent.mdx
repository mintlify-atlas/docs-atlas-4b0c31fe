The synthesizer agent receives individual edge reports from the [edge agent](/api/agents/edge-agent) and produces a unified explanation of how and why a dependency cycle exists.

## Overview

The synthesizer agent:

- Aggregates edge-level dependency explanations
- Explains how individual edges combine to form a cycle
- Interprets why the coupling exists (cautiously)
- Provides maintainability impact notes
- Optionally suggests edges to break (depending on variant)
- Incorporates auxiliary context (boundary/graph insights)

Output is later refined by the [review agent](/api/agents/review-agent).

## Return value

<ResponseField name="explanation" type="str">
  A structured cycle-level explanation with sections varying by variant:
  
  **Variant S0 (default):**
  - Cycle summary
  - How the cycle is formed
  - Why this coupling exists (cautious interpretation)
  - Impact / maintainability notes
  - Reminders / constraints
  
  **Variant S1:**
  - Cycle summary
  - How the cycle is formed
  - Candidate edge(s) to break (pick 1-2)
  - Justification (grounded, cautious)
  - Minimal refactoring strategy
  - Risks / checks
  - Reminders / constraints
  
  **Variant S2:**
  - Cycle summary
  - How the cycle is formed
  - Candidate edges to break (ranked 1-3)
  - Trade-offs (risk, effort, scope)
  - Recommended choice and why
  - Suggested refactoring approach (brief)
  - Reminders / constraints
</ResponseField>

## Variants

The synthesizer agent supports three prompt variants defined in `explain_AS/agents/prompts/prompts_synthesizer.py`:

### S0 - Explanation only (default)

```python
preamble="""You are the Synthesizer Agent.
You receive edge-level explanations for each edge in a dependency cycle.

Rules:
- Stay consistent with the edge reports. Do not invent details.
- No tables, no JSON.
- Avoid overconfidence. If edge reports are unclear, say so.
- Emphasize that the refactoring agent must inspect the actual code.
- If you see truncation notes, assume some context may be missing.

Your job:
- Produce a cycle-level explanation that helps an automated refactoring agent 
  understand the cycle. Do not propose specific edges to break.
"""
```

Produces explanations without suggesting which edges to break.

### S1 - Concrete plan

Includes a minimal plan for breaking the cycle with 1-2 candidate edges. Emphasizes actually improving architecture, not hacky solutions.

### S2 - Trade-off comparison

Provides a ranked shortlist of 2-3 options with pros/cons analysis and a recommended choice.

<Note>
Variants S1 and S2 include explicit rules:
- The cycle must be truly broken, not just moved or made larger
- Do not suggest hacky solutions to break cycles
- Suggestions are framed as recommendations, not commands
</Note>

### Token allocation logic

1. Calculate total input budget after reserving output tokens and safety margin
2. Normalize edge reports (replace empty with "N/A")
3. Combine edge reports and aux context into budget items
4. Use `allocate_token_budgets_even_share_with_redistribution` to fairly allocate tokens
5. Format each edge report block with its allocated budget
6. Format aux context block with its allocated budget
7. Assemble final prompt with all sections

<Note>
The synthesizer uses even-share redistribution: if some edge reports are short, their unused budget is redistributed to longer reports and auxiliary context.
</Note>

## Prompt structure

The synthesizer prompt includes:

1. **Preamble**: Base rules + variant-specific job description
2. **Edge semantics**: Language-specific dependency semantics
3. **Cycle chain**: Pretty-printed list of files in cycle order
4. **Edge reports**: Numbered reports with token budgeting and truncation
5. **Auxiliary context**: Optional boundary/graph insights
6. **Output headings**: Variant-specific section requirements
