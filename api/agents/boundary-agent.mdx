The boundary agent uses heuristics based on file paths, folder structure, and naming conventions to infer likely architectural boundaries within a codebase.

## Overview

The boundary agent:

- Analyzes external connections (incoming/outgoing) for each file in a cycle
- Groups files by folder buckets to identify architectural patterns
- Detects likely boundaries (e.g., domain layers, feature modules)
- Identifies possible boundary violations
- Operates on file paths only (no code analysis)
- Uses cautious interpretation to avoid framework assumptions

Output is typically used as auxiliary context for the [synthesizer agent](/api/agents/synthesizer-agent).

## External connections analysis

```python

  - Samples:

    - src/database/connection.py
- Incoming outside-cycle: 5 total
  - By folder: src/handlers (3), src/api (2)
  - Samples:
    - src/handlers/user_handler.py
    - src/handlers/admin_handler.py
    - src/api/routes.py
    - ... +2 more
```

<Note>
The boundary agent operates purely on file paths and folder structure. It does not analyze code content, making it fast and suitable for large codebases.
</Note>
