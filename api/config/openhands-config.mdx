The `openhands` section of the pipeline configuration controls how OpenHands executes automated refactoring tasks, including Docker runtime settings, iteration limits, and commit messages.

## Overview

OpenHands is an LLM-powered coding agent that performs the actual code refactoring. The pipeline launches OpenHands inside Docker containers, provides cycle explanations as context, and captures all file changes as Git commits.

<Note>
  Each OpenHands run operates on a temporary Git worktree and a dedicated local branch. All changes are committed locally and never pushed to remote repositories.
</Note>

## Configuration

```yaml
openhands:
  runtime_image: "docker.openhands.dev/openhands/runtime:1.4-nikolaik"
  max_iters: 150
  commit_message: "Refactor: break dependency cycle"
```

## Parameters

<ParamField path="openhands.runtime_image" type="string" required>
  Docker image used for the OpenHands runtime environment. This image contains the tools and dependencies needed for code analysis and refactoring.
  
  **Format:** `registry/repository:tag`
  
  **Example:** `docker.openhands.dev/openhands/runtime:1.4-nikolaik`
  
  Common options:
  - `docker.openhands.dev/openhands/runtime:1.4-nikolaik` - Recommended for Python/Node.js projects
  - `docker.all-hands.dev/all-hands-ai/runtime:0.59-nikolaik` - Legacy version
  
  <Note>
    The runtime image must be pulled before running experiments:
    ```bash
    docker pull docker.openhands.dev/openhands/runtime:1.4-nikolaik
    ```
  </Note>
</ParamField>

<ParamField path="openhands.max_iters" type="integer" required>
  Maximum number of LLM iterations allowed for each refactoring task. OpenHands stops after reaching this limit, even if the refactoring is incomplete.
  
  **Example:** `150`
  
  Recommended values:
  - 50-100: Quick experiments, simple cycles
  - 100-150: Standard experiments, moderate complexity
  - 150-200: Complex cycles, multiple modules
  
  <Warning>
    Higher iteration limits increase LLM costs and execution time. Each iteration involves at least one LLM API call.
  </Warning>
</ParamField>

<ParamField path="openhands.commit_message" type="string" required>
  Git commit message used for all refactoring commits. This message is applied to every file change made by OpenHands.
  
  **Example:** `Refactor: break dependency cycle`
  
  Common patterns:
  - `Refactor: break dependency cycle`
  - `Automated refactoring: resolve architectural cycle`
  - `LLM-based refactoring: cycle {cycle_id}`
</ParamField>

## Docker integration

OpenHands runs inside nested Docker containers. The pipeline container must have access to the Docker socket to launch OpenHands containers.

### Required Docker configuration

When starting the pipeline container, ensure:

```bash
docker run --rm -it \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --group-add "$(stat -c '%g' /var/run/docker.sock)" \
  ...
```

This allows OpenHands to:
1. Launch its own Docker containers
2. Mount code volumes
3. Execute refactoring tasks in isolation

## Git worktree workflow

For each refactoring task, the pipeline:

1. Creates a temporary Git worktree in a separate directory
2. Creates a new local branch (e.g., `refactor/cycle-123/mode-explain_E0_S0`)
3. Launches OpenHands with the worktree as the workspace
4. Commits all changes using the configured commit message
5. Extracts the complete patch using `git diff`
6. Removes the temporary worktree

<Note>
  No GitHub credentials are required. All operations use local Git only.
</Note>

## Iteration limit behavior

OpenHands operates in a loop:

1. Reads the current task and code state
2. Calls the LLM to decide the next action
3. Executes the action (edit file, run tests, etc.)
4. Repeats until task complete or `max_iters` reached

When the iteration limit is reached:
- OpenHands stops immediately
- All completed changes are committed
- The task is marked as incomplete
- Results are saved for analysis

<Warning>
  Setting `max_iters` too low may result in incomplete refactorings. Monitor OpenHands logs to determine appropriate limits for your use case.
</Warning>

## Execution environment

OpenHands runs with:

- **Working directory:** Temporary Git worktree containing the repository
- **LLM configuration:** Inherited from the `llm` section via environment variables
- **Prompt context:** Cycle explanation generated by the multi-agent team (or minimal prompt for baseline)
- **Task:** Break the specified dependency cycle

### Environment variables passed to OpenHands

```python
LLM_BASE_URL = config.llm.base_url
LLM_API_KEY = config.llm.api_key
LLM_MODEL = config.llm.model_raw
```

## Output artifacts

Each OpenHands run produces:

- **Execution logs:** Complete stdout/stderr from OpenHands
- **Trajectory file:** Detailed action-observation history
- **Git patch:** Full diff of all changes made
- **Status metadata:** Success/failure, iterations used, error messages

These artifacts are stored in:

```
{results_root}/{experiment_id}/{repo}/{branch}/{mode}/
├── openhands_log.txt
├── openhands_trajectory.json
├── patch.diff
└── status.json
```

## Troubleshooting

### Docker permission errors

If OpenHands cannot launch containers:
1. Verify the Docker socket is mounted: `-v /var/run/docker.sock:/var/run/docker.sock`
2. Verify the Docker group is added: `--group-add "$(stat -c '%g' /var/run/docker.sock)"`
3. Check that the pipeline user has Docker permissions

### Image not found

If the runtime image is not available:
```bash
docker pull docker.openhands.dev/openhands/runtime:1.4-nikolaik
```

### Incomplete refactorings

If refactorings frequently hit the iteration limit:
1. Increase `max_iters` (e.g., from 100 to 150)
2. Review OpenHands logs to understand what it's doing
3. Consider simplifying the task or cycle selection criteria

### LLM connection errors

If OpenHands cannot reach the LLM:
1. Verify the LLM endpoint is accessible from inside Docker
2. Check that `host.docker.internal` is configured correctly
3. Review the LLM server logs for connection attempts
